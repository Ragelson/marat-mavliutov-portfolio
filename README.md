# Портфолио Марата Мавлютова

Личный сайт-портфолио: веб-разработка, инфраструктура и сети, локальные ИИ-системы и эксплуатационная документация — на реальных проектах.

Первая версия — одностраничное приложение (SPA) на русском языке. Backend, база данных и авторизация не нужны: весь контент лежит в TypeScript-файлах.

## Стек

- **React 19** — функциональные компоненты и хуки.
- **TypeScript 6** в строгом режиме (`strict`, `noUncheckedIndexedAccess`).
- **Vite 8** — dev-сервер и сборка.
- **React Router 7** — `BrowserRouter`, обычные URL без `#`.
- **CSS Modules** для компонентов, **CSS custom properties** для дизайн-токенов. Без UI-фреймворков и Tailwind.
- **ESLint** (typescript-eslint, react-hooks), **Vitest** + **React Testing Library**.

Требуется Node.js `^20.19` или `>=22.13`.

## Команды

```bash
npm install          # установить зависимости
npm run dev          # dev-сервер на http://localhost:5173
npm run typecheck    # проверка типов TypeScript
npm run lint         # ESLint
npm test             # тесты (однократный прогон)
npm run test:watch   # тесты в режиме наблюдения
npm run build        # production-сборка в dist/
npm run preview      # локально открыть собранную версию
npm run check        # typecheck + lint + test + build подряд
```

## Структура

```
index.html                 # HTML-оболочка и скрипт ранней установки темы
vite.config.ts             # Vite и настройки тестов
vite-plugins/site-meta.ts  # title/description/Open Graph из конфига; sitemap.xml при наличии site.url
public/favicon.svg         # текстовый знак «ММ»
src/
  main.tsx                 # точка входа: BrowserRouter + App
  App.tsx                  # маршруты: /, /projects/:slug, 404
  config/site.ts           # профиль и контакты
  data/
    projects.ts            # все проекты (published и draft)
    categories.ts          # подписи категорий и порядок фильтра
    directions.ts          # блок «Направления»
  types/project.ts         # типы данных проекта
  lib/
    projects.ts            # выборка опубликованных проектов, фильтр, подписи статусов
    contacts.ts            # список контактов: пустые поля отбрасываются
  hooks/
    useTheme.ts            # тема: localStorage + prefers-color-scheme
    useDocumentMeta.ts     # document.title, description, canonical
    useRouteScroll.ts      # прокрутка и фокус при смене страницы, переходы по якорям
  components/              # переиспользуемые компоненты (Header, Footer, ProjectCard, ...)
  pages/                   # HomePage (и её секции), ProjectPage, NotFoundPage
  styles/
    tokens.css             # цвета, шрифты, отступы для обеих тем
    globals.css            # базовые стили, .container, .button, .visually-hidden
  test/                    # настройка тестов и хелпер renderApp
```

Тесты лежат рядом с кодом, который проверяют (`*.test.ts(x)`).

Импорты внутри проекта пишутся с расширением (`'./App.tsx'`). Так конфиг Vite может импортировать данные из `src/` (для метаданных и sitemap) без предупреждений о будущей нативной загрузке конфигурации.

## Как обновлять контент

### Профиль и контакты

Всё в `src/config/site.ts`: имя, подпись `delure`, город, заголовок, текст первого экрана, описание для поисковиков и контакты.

Необязательные контакты (`email`, `telegram`, `linkedin`) просто не указывайте, пока их нет, — на сайте они не появятся. Когда появится почта, кнопка «Написать на почту» станет основной, а GitHub останется рядом. Пока указан только GitHub, кнопка в блоке «Контакты» так и называется — «GitHub».

### Добавить проект

1. Откройте `src/data/projects.ts` и добавьте объект в массив `projects`. Типы из `src/types/project.ts` подскажут поля, TypeScript не даст пропустить обязательные.
2. Обязательные поля: `slug` (часть адреса `/projects/<slug>`), `title`, `summary`, `categories`, `stack`, `featured`, `publicationStatus`.
3. Необязательные: `kind` (коммерческий/учебный), `projectStatus` (в разработке/завершён), `role`, `case` (разделы кейса), `links`, `images`, `diagram`.
4. Разделы кейса (`case.context`, `constraints`, `work`, `result`, `limitations`) — это абзацы `paragraphs` и/или списки `items`. `decisions` — пары «решение — причина». Пустой или отсутствующий раздел на странице не выводится, поэтому заглушки не нужны.
5. Порядок в массиве — порядок на главной; проекты с `featured: true` выводятся первыми.

Компоненты менять не нужно: карточка, страница кейса, фильтр и ссылки в «Направлениях» строятся из данных. Кнопка категории появляется в фильтре, как только в ней есть хотя бы один опубликованный проект.

В будущем страницы `/frontend`, `/infrastructure`, `/ai` можно собрать из тех же данных функцией `filterByCategory` из `src/lib/projects.ts`, без копирования проектов.

### Draft и published

| | `published` | `draft` |
|---|---|---|
| Карточка на главной | есть | нет |
| Страница `/projects/<slug>` | открывается | 404 |
| Ссылки в «Направлениях» | есть | нет |
| sitemap.xml (если включён) | есть | нет |

**Draft не означает конфиденциальность.** Данные draft-проектов попадают в JavaScript-сборку и в репозиторий. Не храните в них ничего, что нельзя показать публично: адреса, ключи, внутренние документы, неподтверждённые показатели.

### Скриншоты

1. Положите файл в `public/projects/<slug>/`, например `public/projects/vinc/calendar.webp`. Лучше WebP или AVIF шириной 1600–2000 px.
2. Добавьте в проект:

```ts
images: [
  {
    src: '/projects/vinc/calendar.webp',
    alt: 'Календарь задач в планере Vinc: неделя с задачами по сферам',
    width: 1600,
    height: 1000,
    caption: 'Календарь задач', // необязательно
  },
],
```

`width` и `height` обязательны: по ним браузер заранее резервирует место и вёрстка не прыгает. `alt` описывает, что изображено, а не «скриншот». Изображения на странице кейса загружаются лениво (`loading="lazy"`). Используйте только реальные скриншоты, которые разрешено публиковать.

### Схемы

Схемы VivoAI и межофисной сети нарисованы HTML/CSS в `src/components/Diagrams/` (обычный текст, читается скринридером, работает в обеих темах). Проект подключает схему полем `diagram: 'vivoai-flow' | 'office-network'`. Обе схемы подписаны как упрощённые; в схеме сети только условные «Офис A» и «Офис B», без адресов и конфигураций.

## Как устроена тема

- Цвета заданы переменными в `src/styles/tokens.css`: значения для `:root[data-theme='light']` и `:root[data-theme='dark']`. Там же выставлен `color-scheme`, поэтому полосы прокрутки и поля формы тоже меняют тему.
- Маленький скрипт в `index.html` выставляет `data-theme` **до** отрисовки страницы, чтобы не было вспышки неправильной темы. Порядок такой: сохранённый выбор → системная настройка `prefers-color-scheme`.
- Хук `useTheme` хранит тему в состоянии, синхронизирует атрибут на `<html>` и сохраняет выбор в `localStorage` только после ручного переключения. Пока выбора нет, тема следует за системной настройкой.
- Если `localStorage` недоступен (приватный режим, запрет в браузере), сайт работает, просто выбор не запоминается.
- Переключатель — кнопка с `role="switch"` и доступным именем «Тёмная тема». Состояние видно по положению ползунка и иконке, а не только по цвету.

## Несколько решений, о которых стоит знать

- **Отфильтрованный список проектов не хранится в состоянии.** В состоянии только выбранная категория, список каждый раз вычисляется из исходных данных. Хранить нечего синхронизировать — меньше ошибок.
- **Прокрутка при навигации — свой хук `useRouteScroll`.** `BrowserRouter` сам прокруткой не управляет. Хук возвращает позицию при «Назад/Вперёд», ждёт появления секции при переходе на `/#projects` с другой страницы и переводит фокус на новое содержимое. Шапка не перекрывает секции благодаря `scroll-margin-top`.
- **Ссылки шапки ведут на `/#секция`**, поэтому работают и со страниц кейсов.
- **Мобильное меню** — обычная раскрывающаяся навигация, а не модальное окно: `aria-expanded` и `aria-controls`, закрывается при выборе пункта и по Escape (фокус возвращается на кнопку).
- **Внешние ссылки** открываются в новой вкладке, и скринридер об этом предупреждает (`ExternalLink`).

## Подготовка к публикации

1. `npm run check` — все проверки и сборка.
2. Готовый сайт лежит в `dist/`: это статические файлы, подойдёт любой статический хостинг.
3. **Нужен SPA fallback.** Сервер должен отдавать `index.html` на любой неизвестный путь, иначе прямое открытие `/projects/vivoai` или обновление страницы кейса вернёт ошибку 404 хостинга. После публикации проверьте отдельно: прямое открытие `/projects/vivoai`, обновление страницы на кейсе и несуществующий адрес.
   - nginx: `try_files $uri /index.html;`
   - Netlify: файл `public/_redirects` со строкой `/* /index.html 200`
   - Vercel: `rewrites` на `/index.html` в `vercel.json`

   Конфигурация конкретного хостинга в проект пока не добавлена, потому что хостинг не выбран.
4. **GitHub Pages** не поддерживает обычные SPA rewrites. Для него нужно сознательно выбрать один подход:
   - перейти на `HashRouter` (адреса вида `/#/projects/vivoai`);
   - заранее генерировать HTML для каждого маршрута (prerender);
   - или трюк с копированием `index.html` в `404.html` (страницы откроются, но сервер будет отвечать статусом 404).
5. **Размещение в подпапке** (например, `https://user.github.io/portfolio/`): нужно согласованно задать `base: '/portfolio/'` в `vite.config.ts` и `basename="/portfolio"` у `BrowserRouter` в `src/main.tsx`.
6. Когда появится домен, укажите его в `site.url` (`src/config/site.ts`). Тогда при сборке появится `dist/sitemap.xml` (только опубликованные проекты), а в браузере у каждой страницы появится `<link rel="canonical">`. Выдуманный домен заранее не указан.

## Ограничения SPA

- Сервер отдаёт один и тот же `index.html` на все адреса. Заголовок, описание и canonical для кейсов выставляются JavaScript-ом уже в браузере.
- Мессенджеры и соцсети при построении превью ссылки обычно не выполняют JavaScript. Поэтому у всех страниц превью будет общим, с заголовком и описанием главной. Индивидуальных превью кейсов сейчас нет.
- Поисковики, которые выполняют JavaScript, увидят содержимое, но это менее надёжно, чем готовый HTML. Сайт нельзя назвать полностью SEO-оптимизированным только из-за смены `document.title`.
- Для 404 сервер всё равно отвечает статусом 200 (страница «не найдено» рисуется на клиенте).
- Если понадобятся индексация кейсов и отдельные превью, достаточно добавить предварительную генерацию HTML (prerender) для `/` и `/projects/<slug>`. Переходить на другой фреймворк сейчас не нужно.

## Недостающие данные и материалы

Пока этого нет, соответствующие элементы на сайте не показываются.

**Контакты и адрес сайта**
- Полный email (известна только часть имени ящика — адрес не выдумывался).
- Подтверждённые ссылки на Telegram, LinkedIn и другие соцсети, если они нужны.
- Production-домен, если он будет (для `site.url`, canonical и sitemap).
- Фотография не обязательна; если понадобится, только реальная.

**VivoAI**
- Показатели ждут подтверждения и разрешения на публикацию и на сайте не выводятся:
  - 100+ документов в базе;
  - 8 пользователей;
  - «неделя → 30 минут» на поиск — со слов директора, не инструментальный замер.
- Разрешение на публикацию внутренних материалов (скриншоты интерфейса, детали схемы БД).
- Публичная ссылка и репозиторий неизвестны.
- Тип проекта (коммерческий, внутренний) не указан.

**Планер Vinc**
- Даты работы и текущий статус проекта.
- Скриншоты, которые можно публиковать.

**Межофисная сеть**
- Статус и период работ не указаны. Реальные адреса, ключи и конфигурации не публикуются намеренно.

**Vivocomp (draft)**
- Конкретные изменения, точная роль, публичный URL и измеримые результаты.
- В загруженном HTML-резюме есть подробности (разделы сайта, шаблон, cookie-баннер, адрес сайта). Их нужно подтвердить, прежде чем переносить в данные и публиковать кейс.

**Регламент диагностики КТСО (draft)**
- Состав оборудования, содержание регламента и какие материалы допустимо публиковать. Диагностические процедуры не выдумывались и не публикуются.

**Учебный сайт «Атака титанов» (draft)**
- Точный URL. В HTML-резюме указан адрес на `ragelson.github.io`; его нужно проверить, прежде чем добавлять.
- Используемые технологии и реализованные функции.
- Изображения — только свои или с подтверждённым правом на использование.

**Перед публикацией сайта**
- Проверьте доступность внешних проектов (сейчас в кейсах есть одна ссылка — `https://vincerepsy.com`).
