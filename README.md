# Портфолио Марата Мавлютова

Личный сайт-портфолио: веб-разработка, инфраструктура и сети, локальные ИИ-системы и эксплуатационная документация — на реальных проектах.

Первая версия — одностраничное приложение (SPA) на русском языке. Backend, база данных и авторизация не нужны: весь контент лежит в TypeScript-файлах.

Сайт публикуется на GitHub Pages: https://ragelson.github.io/marat-mavliutov-portfolio/ (адрес заработает после первой публикации, см. «Публикация на GitHub Pages»).

## Стек

- **React 19** — функциональные компоненты и хуки.
- **TypeScript 6** в строгом режиме (`strict`, `noUncheckedIndexedAccess`).
- **Vite 8** — dev-сервер и сборка.
- **React Router 7** — `BrowserRouter`, обычные URL без `#`.
- **CSS Modules** для компонентов, **CSS custom properties** для дизайн-токенов. Без UI-фреймворков, Tailwind и библиотек анимации.
- Шрифты **Onest** (основной) и **JetBrains Mono** (номера и технические подписи) — пакеты `@fontsource-variable/*`, файлы лежат в сборке, лицензия SIL Open Font License 1.1. Внешние сервисы шрифтов не используются.
- **ESLint** (typescript-eslint, react-hooks), **Vitest** + **React Testing Library**.

Требуется Node.js `^20.19` или `>=22.13`.

```bash

```

Импорты внутри проекта пишутся с расширением (`'./App.tsx'`). Так конфиг Vite может импортировать данные из `src/` (для метаданных и sitemap) без предупреждений о будущей нативной загрузке конфигурации.

## Как обновлять контент

### Профиль и контакты

Всё в `src/config/site.ts`: имя, публичный знак `delure` (в шапке выводится как DELURE), город, текст первого экрана, описание для поисковиков и контакты.

Необязательные контакты (`email`, `telegram`, `linkedin`) просто не указывайте, пока их нет, — на сайте они не появятся. Каждый контакт в финальном блоке — крупная строка с честной подписью канала: «Написать на почту», «Telegram», «GitHub». Пока указан только GitHub, строка так и называется — «GitHub».

### Добавить проект

1. Откройте `src/data/projects.ts` и добавьте объект в массив `projects`. Типы из `src/types/project.ts` подскажут поля, TypeScript не даст пропустить обязательные.
2. Обязательные поля: `slug` (часть адреса `/projects/<slug>`), `title`, `summary`, `categories`, `stack`, `featured`, `publicationStatus`.
3. Необязательные: `workType` (тип работы одной фразой), `highlights` (2–3 пункта для главной), `kind` (коммерческий/учебный), `projectStatus` (в разработке/завершён), `role`, `case` (разделы кейса), `links`, `images`, `diagram`.
4. Разделы кейса (`case.context`, `constraints`, `work`, `result`, `limitations`) — это абзацы `paragraphs` и/или списки `items`. `decisions` — пары «решение — причина». Пустой раздел не выводится, нумерация разделов идёт подряд.
5. Порядок в массиве — порядок на главной.

Компоненты менять не нужно: главная, страница кейса и следующий кейс строятся из данных. Будущие страницы `/frontend`, `/infrastructure`, `/ai` можно собрать функцией `filterByCategory` из `src/lib/projects.ts`, без копирования проектов.

### Как проект попадает на главную

- **Избранный** (`featured: true`, `published`) — отдельная крупная композиция. Главный материал: первое изображение из `images`, а если его нет — схема из `diagram`. Раскладка зависит от материала: изображение крупно слева и текст справа; у схем свои раскладки.
- **Другие работы** — компактный список: опубликованные неизбранные проекты (со ссылкой на кейс) и `listed`-проекты (без ссылки). Учебный проект отмечен плашкой «Учебный проект».

### Draft, listed и published

| | `published` | `listed` | `draft` |
|---|---|---|---|
| На главной | композиция или строка со ссылкой | строка без ссылки | нет |
| Страница `/projects/<slug>` | открывается | 404 | 404 |
| Отдельный HTML-файл и sitemap.xml | есть | нет | нет |

`listed` подходит, когда о работе можно сказать одну-две подтверждённые фразы, а материалов на кейс пока нет. Сейчас так показаны Vivocomp, регламент КТСО и «Атака титанов». Когда материалы появятся, заполните `case` и поменяйте статус на `published`.

**Ни один статус не означает конфиденциальность.** Данные всех проектов попадают в JavaScript-сборку и в репозиторий. Не храните там ничего, что нельзя показать публично: адреса, ключи, внутренние документы, неподтверждённые показатели.

### Скриншоты

1. Положите файл в `public/projects/<slug>/`, например `public/projects/vinc/calendar.webp`. Лучше WebP или AVIF шириной 1600–2000 px.
2. Добавьте в проект (путь пишется от корня `public`, префикс GitHub Pages подставится сам):

```ts
images: [
  {
    src: '/projects/vinc/calendar.webp',
    alt: 'Календарь задач в планере Vinc: неделя с задачами по сферам',
    width: 1600,
    height: 1000,
    caption: 'Календарь задач', // необязательно
  },
],
```

`width` и `height` обязательны: по ним браузер заранее резервирует место и вёрстка не прыгает. `alt` описывает, что изображено, а не «скриншот». Используйте только реальные скриншоты, которые разрешено публиковать, без персональных данных.

Первое изображение становится главным материалом: на главной оно заменяет схему в композиции проекта, а на странице кейса выводится крупно под заголовком. Остальные изображения попадают в раздел «Материалы». Изображения ниже первого экрана загружаются лениво.

### Схемы

Схемы нарисованы HTML/CSS в `src/components/Diagrams/`: это обычный текст, он читается скринридером и работает в обеих темах. Проект подключает схему полем `diagram`:

- `vinc-architecture` — слои frontend Vinc: страницы, модули, DTO, API-клиент; REST API и платёжный провайдер — вне frontend;
- `vivoai-flow` — цепочка «менеджер → Open WebUI → Ollama · Qwen3:14B → Pipe-функция → PostgreSQL» в локальном контуре и отдельно внешние Yandex API и 4Dealer API. Заливкой выделена собственная логика: Pipe-функция и схема БД;
- `office-network` — условные «Офис A» и «Офис B», прямой WireGuard-туннель между роутерами и отдельный административный туннель. Без адресов, ключей и конфигураций.

Все схемы подписаны как упрощённые и показывают только подтверждённые компоненты.

## Оформление

- **Палитра:** графит `#111214`, тёплый светлый `#F1EFE8`, оранжевый `#FF6B35`, приглушённый серый для вторичного текста. Оранжевый — заливки, крупные элементы и фон с тёмным текстом. Для мелкого оранжевого текста на светлом фоне используется более тёмный оттенок (`--color-accent-text`), потому что `#FF6B35` на `#F1EFE8` не проходит контраст. Все пары текста и фона проверены на WCAG AA (не ниже 5:1).
- **Поверхности:** `.surface-inverse` (тёмная панель) и `.surface-accent` (оранжевый финал) переопределяют те же токены внутри секции, поэтому компоненты сами подстраиваются под фон. `.blueprint` — тонкая техническая сетка под схемами.
- **Типографика:** крупные размеры заданы через `clamp()` в `tokens.css` (`--text-display` для имени, `--text-3xl` для заголовков). Длина строки основного текста ограничена `--measure` (68ch).
- **Движение:** короткое появление элементов первого экрана (до 0,5 с) и мягкое появление крупных блоков при прокрутке — только CSS. Появление при прокрутке использует scroll-driven animations; браузеры без поддержки показывают блоки сразу. При `prefers-reduced-motion: reduce` анимации отключены. Сайт полностью читается без движения.


## Как устроена тема

- Цвета заданы переменными в `src/styles/tokens.css`: значения для `:root[data-theme='light']` и `:root[data-theme='dark']`. Тёмная тема — не инверсия: у неё свои фоны (графит и приподнятый графит для панелей), подписи и фокус (оранжевый). Там же выставлен `color-scheme`, поэтому полосы прокрутки и поля формы тоже меняют тему. Изображения фильтрами не инвертируются.
- Маленький скрипт в `index.html` выставляет `data-theme` **до** отрисовки страницы, чтобы не было вспышки неправильной темы. Порядок такой: сохранённый выбор → системная настройка `prefers-color-scheme`.
- Хук `useTheme` хранит тему в состоянии, синхронизирует атрибут на `<html>` и сохраняет выбор в `localStorage` только после ручного переключения. Пока выбора нет, тема следует за системной настройкой.
- Если `localStorage` недоступен (приватный режим, запрет в браузере), сайт работает, просто выбор не запоминается.
- Переключатель — кнопка с `role="switch"` и доступным именем «Тёмная тема». Состояние видно по положению ползунка и иконке, а не только по цвету.

## Несколько решений, о которых стоит знать

- **Списки проектов вычисляются из данных**, а не хранятся в состоянии: выборки лежат в `src/lib/projects.ts` и покрыты тестами.
- **Прокрутка при навигации — свой хук `useRouteScroll`.** `BrowserRouter` сам прокруткой не управляет. Хук возвращает позицию при «Назад/Вперёд», ждёт появления секции при переходе на `/#work` с другой страницы и переводит фокус на новое содержимое. Шапка не перекрывает секции благодаря `scroll-margin-top`.
- **Ссылки шапки ведут на `/#секция`**, поэтому работают и со страниц кейсов.
- **Мобильное меню** — обычная раскрывающаяся навигация, а не модальное окно: `aria-expanded` и `aria-controls`, плавно раскрывается, закрывается при выборе пункта и по Escape (фокус возвращается на кнопку). Закрытые пункты скрыты через `visibility` и недоступны с клавиатуры.
- **Внешние ссылки** открываются в новой вкладке, и скринридер об этом предупреждает (`ExternalLink`).

## Публикация на GitHub Pages

Публикацию выполняет workflow `.github/workflows/deploy.yml` при каждом push в ветку `main` (или вручную: вкладка Actions → Deploy to GitHub Pages → Run workflow). Он ставит зависимости, запускает `npm run check` (типы, ESLint, тесты, сборка) и публикует `dist/`. Если проверки падают, сайт не обновляется.

**Один раз включите Pages:** Settings → Pages → Build and deployment → Source: **GitHub Actions**. Без этого шаг публикации завершится ошибкой.

### Как обычные URL работают без SPA rewrites

GitHub Pages не умеет отдавать `index.html` на любой адрес. Поэтому при сборке плагин `vite-plugins/site-meta.ts` создаёт статические файлы:

| Файл | Что открывает GitHub Pages |
|---|---|
| `index.html` | главную `/marat-mavliutov-portfolio/` |
| `projects/<slug>.html` | `/marat-mavliutov-portfolio/projects/<slug>` (Pages отдаёт `x.html` по адресу `/x`) |
| `404.html` | любой неизвестный адрес, включая draft и listed-проекты; ответ со статусом 404 |

Внутри каждого файла та же оболочка приложения: React Router сам рисует нужную страницу. Отличаются только `<title>`, description, Open Graph и canonical. Поэтому прямое открытие кейса и обновление страницы работают, а у ссылки на кейс в мессенджере свой заголовок и описание. Новый опубликованный проект получает свой файл автоматически.

### Сайт в подпапке

Сайт проекта на GitHub Pages открывается из подпапки `/marat-mavliutov-portfolio/`. Workflow берёт путь из настроек Pages и передаёт его в сборку через переменную `BASE_PATH`. Vite использует его как `base`, а `BrowserRouter` получает тот же путь (`import.meta.env.BASE_URL`) как `basename`. Локально `BASE_PATH` не задан, и сайт работает от `/`.

Проверить сборку для подпапки локально:

```bash
BASE_PATH=/marat-mavliutov-portfolio/ npm run build
npm run preview   # откройте http://localhost:4173/marat-mavliutov-portfolio/
```

`vite preview` отдаёт `index.html` на любой путь и поэтому не повторяет правила GitHub Pages один в один. После каждой публикации проверьте на настоящем сайте: прямое открытие `/projects/vivoai`, обновление страницы кейса и несуществующий адрес.

### Свой домен

1. Укажите домен в Settings → Pages → Custom domain.
2. Поменяйте `site.url` в `src/config/site.ts` (от него зависят canonical, og:url и `sitemap.xml`).
3. `base` менять не нужно: для собственного домена workflow сам передаст `/`.

### Другой хостинг

Сборка (`dist/`) — обычные статические файлы. На хостинге с SPA fallback (nginx `try_files $uri /index.html;`, Netlify `_redirects`, Vercel `rewrites`) она тоже работает; дополнительные HTML-файлы там не мешают. Конфигурации других хостингов в проекте нет.

## Ограничения SPA

- Содержимое страниц рисует JavaScript в браузере. В статическом HTML есть только метаданные (заголовок, описание, Open Graph, canonical), а не текст кейсов.
- Мессенджеры и соцсети видят отдельный заголовок и описание для каждого кейса. Картинки превью (`og:image`) нет: нужного изображения пока нет.
- Поисковики, которые выполняют JavaScript, увидят текст, но это менее надёжно, чем готовый HTML. Сайт нельзя назвать полностью SEO-оптимизированным.
- `robots.txt` для сайта в подпапке не создаётся: поисковики читают его только в корне домена (`ragelson.github.io`). Sitemap можно добавить вручную в Google Search Console или Яндекс Вебмастере.
- Если понадобится текст кейсов прямо в HTML, следующий шаг — предварительная генерация (prerender) тех же маршрутов при сборке. Переходить на другой фреймворк для этого не нужно.

## Недостающие данные и материалы

Пока этого нет, соответствующие элементы на сайте не показываются.

**Изображения для окончательного вида** (сейчас вместо них — схемы, а не макеты)
- **Vinc** — главное: 2–4 скриншота интерфейса (календарь, доска задач, окно задачи, лендинг) без персональных данных. Публичная страница vincerepsy.com из среды разработки была недоступна, поэтому снимков нет. Если снимать публичные страницы, нужно подтвердить, что их текущий вид отражает вашу работу.
- **VivoAI** — скриншот интерфейса Open WebUI с обезличенными данными, если его разрешено публиковать.
- **Межофисная сеть** — не требуется: схема условная намеренно.
- **Vivocomp, «Атака титанов»** — скриншоты понадобятся, когда проекты станут полноценными кейсами.

**Контакты и адрес сайта**
- Полный email. В загруженном HTML-резюме указан адрес почты; на сайт он не добавлен, потому что раньше вы указали, что полный адрес неизвестен. Если его можно публиковать, впишите `email` в `src/config/site.ts`.
- Подтверждённые ссылки на Telegram, LinkedIn и другие соцсети, если они нужны.
- Собственный домен, если он будет. Сейчас `site.url` указывает на адрес GitHub Pages.
- Фотография не обязательна; если понадобится, только реальная.

**VivoAI**
- Показатели ждут подтверждения и разрешения на публикацию и на сайте не выводятся:
  - 100+ документов в базе;
  - 8 пользователей;
  - «неделя → 30 минут» на поиск — со слов директора, не инструментальный замер.
- Разрешение на публикацию внутренних материалов (скриншоты интерфейса, детали схемы БД).
- Публичная ссылка и репозиторий неизвестны.
- Тип проекта (коммерческий, внутренний) не указан.

**Планер Vinc**
- Даты работы и текущий статус проекта.
- Скриншоты, которые можно публиковать.

**Межофисная сеть**
- Статус и период работ не указаны. Реальные адреса, ключи и конфигурации не публикуются намеренно.

**Vivocomp (listed — строка в «Других работах»)**
- Конкретные изменения, точная роль, публичный URL и измеримые результаты.
